<h3>사용 기술</h3> 
  <ul>
    <li>Back-end : Java, Spring</li>
    <li>Front-end : HTML, CSS, JavaScript, JQuery</li>

  <h4>프로젝트를 시작하기에 앞서.</h4>
  첫 프로젝트로 그룹웨어 프로젝트를 하게되었는데 학원 커리큘럼상 굉장히 빠듯한 일정이었다.
  그렇기에 회사의 업종을 선택하지 못했던 부분이 아쉬웠다.
  가장 먼저 학원에서 배웠던 기술들을 최대한 많이 응용해보려고 노렸했고, 기능들을 구현하면서 DB를 어떻게 해야할지. 어떤 방식으로 어떤 스킬을 이용하여 접근해야할지 많은 것을 배울 수 있었던
  첫 프로젝트였다. 
  배웠던 내용들을 전체적으로 응용해보려고 해서 해당 내용들을 다시 복습하며 어떤 방식으로 이용 할 수 있을지 생각해보며 나 자신이 어느정도인지 한번 더 느꼈고 전체적인 내용들을 복습 할 수 있는 계기가 되었다.

<h3>담당 기능</h3>
 <ul>
   <li>CRUD를 이용한 사원 조회, 추가, 업데이트, 삭제</li>
   <li>Ajax비동기를 이용한 출근/퇴근 기록</li>
   <li>Spring 스케줄러를 이용하여 일정 시간마다 DB의 근태에 NULL 값을 부여하고 출근/퇴근 버튼 클릭시 해당 값을 업데이트</li>   
 </ul>

 <h3>어려웠던 부분</h3>
   첫 프로젝트인 만큼 ERD를 구성하는 부분에서부터 착오가 많았다. ERD를 구성한 후에도 작업중에 회의를 하면서 수정을 많이 했고, 결과적으로는 첫 프로젝트라 다들 만족했던 것 같다. 
   작업하면서 다 같이 느낀점은 다들 스킬이 부족해서 어떤 스킬을 사용할지 생각하고 ERD를 구성했으면 더욱 편했을거같았다고 생각했고 한가지 기능을 구현함에 있어서 사용할 수 있는 기술은 많았고
   앞으로는 추후 유지보수나 추가될 가능성이 있는 기능들을 생각해서 ERD를 구성해야겠다.
   또한 사원 추가에서 이미지 첨부에서 굉장히 애를 먹었다. 배웠던 학습자료를 보고 따라했지만, 해당 코드에서 여러가지 이미지를 첨부하는 것이 아니라면 반복문을 쓸 필요가 없었다.

<h3>개선해야 할 부분</h3>
  개발자로서 가장 쉬우면서 중요한 부분이 주석이라고 다시 한번 크게 느꼈다.
  단순히 기능 부분에 어떤기능인지 주석을 추가하는 것 뿐 아니라 사용한 API나 간단한 기능 구현 주석에도 코드를 넣으면 더 좋았을 것 같다.

<h3>트래블 슈팅</h3>
  Spring Scheduler로 일정시간마다 DB의 근태 테이블에 Null 값을 부여하고 출근/퇴근 버튼 클릭시 출근/퇴근의 값이 업데이트 되도록 하려고 했다.
  <br>
  처음에는 컨트롤러와 비지니스 로직에서 해당 코드를 입력하여 처리하려고 했는데 되지 않아서 구글링을 해보고 학습자료를 다시 한번 찾아봤다.
  <br>배웠던 내용을 찾아보고 해당 코드는 servlet-context.xml에 입력해야한다는걸 알았고 해당 코드를 다시 servlet-context.xml에 입력하여 시도했는데 작동하지 않았다.
  <br>여기서 한참 고민하다가 혹시나 bean 메서드를 카멜 방식으로 입력하지 않아서 안되는건가 하고 카멜방식으로 수정했고 그때서야 해당 스케줄러가 잘 작동했다.
  <br>수업시간에 항상 선생님이 변수명, 메서드명, 클래스명에서 카멜표현식으로 해야한다고 하셨었는데 가장 기본적인것을 놓치고있었다. 다시 한번 기본적인것부터 놓치지 말아야겠다는 생각을 했다.
